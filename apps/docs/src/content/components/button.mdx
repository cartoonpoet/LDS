<h2 id="overview">Overview</h2>

버튼은 LDS v3에서 가장 빠르게 결정이 필요한 액션 프리미티브입니다.
화면 안에서 **무엇이 1순위 CTA인지, 어떤 액션이 보조인지**를 한눈에 구분하게 만드는 것이 핵심입니다.

<DecisionGrid>
  <DecisionCard title="Best for">
    한 단계 안에서 사용자가 지금 눌러야 할 핵심 액션을 명확히 보여줄 때 적합합니다.
  </DecisionCard>
  <DecisionCard title="Choose by emphasis">
    `solid`는 기본 CTA, `outline`은 보조 액션, `gradient`는 화면 전체에서 가장 강한 한 개의 CTA에 맞습니다.
  </DecisionCard>
  <DecisionCard title="Avoid when">
    같은 액션 그룹 안에 시각적으로 강한 버튼을 여러 개 두어 우선순위가 흐려지는 상황은 피하는 편이 좋습니다.
  </DecisionCard>
</DecisionGrid>

>

<h2 id="when-to-use">When to use</h2>

<Checklist
  items={[
    <>저장, 제출, 승인처럼 화면 목표를 완료시키는 액션에 사용합니다.</>,
    <>보조 액션은 outline 또는 secondary tone으로 분리해 주 행동과 거리를 둡니다.</>,
    <>loading 상태가 길어질 수 있으면 버튼 라벨은 유지하고 진행 상태만 추가해 맥락 손실을 줄입니다.</>
  ]}
/>

<h2 id="variants">Variants</h2>

<Checklist
  items={[
    <><code>solid</code>: 가장 일반적인 기본 CTA. 업무형 폼 저장/확인 버튼에 우선 사용합니다.</>,
    <><code>outline</code>: 취소, 보류, 이전 단계 이동처럼 보조 액션에 적합합니다.</>,
    <><code>gradient</code>: 랜딩 성격이 있거나 강한 전환이 필요한 지점에서 한 번만 사용하는 편이 안전합니다.</>,
    <><code>tone</code>: semantic intent를 보조적으로 전달하되, 같은 화면에서 tone 수를 과하게 늘리지 않습니다.</>
  ]}
/>

<h2 id="usage-guidance">Usage guidance</h2>

<GuidanceGrid>
  <GuidanceCard title="Do">
    한 블록 안에서는 버튼 간 역할 차이가 바로 보이도록 size보다 variant와 tone 우선순위를 먼저 정리합니다.
  </GuidanceCard>
  <GuidanceCard title="Don't" tone="dont">
    gradient 버튼을 여러 개 배치하거나 danger tone을 일반 완료 액션에 쓰지 않습니다.
  </GuidanceCard>
</GuidanceGrid>

<Callout title="Quick rule" tone="caution">
  같은 액션 그룹 안에 gradient 버튼을 여러 개 두지 않는 것이 좋습니다.
</Callout>
