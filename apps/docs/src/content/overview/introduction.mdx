<h2 id="why-lds-matters">LDS가 필요한 이유</h2>

LDS는 법무 시스템 전반에서 반복되는 화면 패턴을 하나의 기준으로 정리하기 위해 만들어진 디자인 시스템입니다.  
단순히 컴포넌트를 모아두는 데서 그치지 않고, 제품이 커져도 일관된 경험을 유지할 수 있도록 디자인 원칙과 구현 규칙을 함께 제공합니다.

법무 업무 화면은 정보 밀도가 높고, 입력·검토·승인 같은 흐름이 자주 반복됩니다.  
그래서 화면마다 다른 방식으로 구현하기보다, 공통 언어와 공통 컴포넌트로 연결하는 것이 훨씬 중요합니다.

<Callout>
  이 문서는 디자이너와 개발자가 같은 기준으로 빠르게 판단할 수 있도록 만든 공개 가이드입니다. 시각 확인과 실제 컴포넌트 검증은 Storybook에서 함께 진행합니다.
</Callout>

<h2 id="principles">운영 원칙</h2>

- 화면마다 새로 만들기보다, 먼저 재사용 가능한 토큰과 기본 컴포넌트로 문제를 해결합니다
- 하드코딩된 값 대신 의미 기반 토큰을 사용해 서비스 전체의 일관성을 유지합니다
- 디자인과 코드 문서를 분리하지 않고 같은 저장소 안에서 함께 관리합니다
- 법무 도메인 특성에 맞게 높은 정보 밀도 속에서도 읽기 쉬운 인터페이스를 우선합니다

<h2 id="current-v3-surface">현재 v3 구성</h2>

현재 v3는 파운데이션 토큰과 기본 폼/액션 컴포넌트를 중심으로 정리되어 있습니다.  
버튼, 인풋, 셀렉트처럼 가장 자주 쓰는 기초 레이어부터 먼저 안정적으로 쌓고, 이후 데이터 테이블, 드롭다운, 승인선, 문서 뷰어처럼 법무 시스템에 특화된 패턴으로 확장해 나갑니다.
